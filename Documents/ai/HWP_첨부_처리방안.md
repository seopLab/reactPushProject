# HWP 첨부 처리 방안

WBS 5.23 · 담당 정민 · 2026-11-19 · 상태: 방안 결정 완료, 구현 대기

## 1. 확인한 사실 (2026-11-19)

청약홈 APT 분양정보 목록 첫 페이지 공고 8건의 상세 페이지 첨부를 직접 확인했다.

| 공고 | 모집공고문 형식 |
|---|---|
| 고양 한신더휴 퍼스트원 | PDF |
| 왕숙 한신더휴 센텀(공공분양) | PDF |
| 더샵 천안라크원 | PDF |
| 두산위브 트레지움 익산 | PDF |
| 구미 파크원 데시앙 | PDF |
| 호반써밋 초량 | PDF (정정 공고) |
| 더샵 트리센트 | PDF |
| 해링턴 플레이스 문래 | PDF |

→ **1차 범위(청약홈 APT)는 8/8 PDF.** HWP 문제는 2차 범위인 LH·SH·마이홈 임대 공고에서 생길 가능성이 크다 (LH 첨부 형식은 EC2 서울에서 별도 확인 필요).

## 2. 결정

| 순서 | 첨부 상황 | 처리 |
|---|---|---|
| 1 | PDF 있음 | PDF 를 Gemini 에 그대로 입력 (페이지 번호 근거 확보 가능) |
| 2 | HWPX 만 있음 | `kr.dogfoot:hwpxlib` 로 본문·표 텍스트 추출 → 텍스트로 Gemini 입력 |
| 3 | HWP(5.x) 만 있음 | `kr.dogfoot:hwplib` 로 텍스트 추출 → 텍스트로 Gemini 입력 |
| 4 | 추출 실패 | `notice_analyses.status = FAILED`, 앱은 "공고문 원문에서 확인" 안내 + 원문 링크만 표시 |

- 두 라이브러리 모두 순수 자바라 Spring Boot 서버(ai 패키지)에 의존성만 추가하면 된다. Maven Central 확인: hwplib 1.1.9, hwpxlib 1.0.5
- LibreOffice 변환은 쓰지 않는다: 서버에 프로그램 설치가 필요하고, 최신 HWP 형식 지원이 불확실하다
- 텍스트 입력은 페이지 번호가 없으므로 `evidence.page` 는 `null`, `quote` 만 남긴다 (AI 결과 항목 정의 참고)

## 3. 남은 일 (구현)

1. LH 공고 첨부 형식 실제 확인 (EC2 서울, 5.9 LH 수집과 함께)
2. ai 패키지에 `AttachmentTextExtractor` (PDF 그대로 / HWPX / HWP 분기) 추가
3. HWP·HWPX 샘플 공고 각 1건으로 추출 → 분석 결과 확인
